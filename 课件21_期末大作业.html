期末大作业 — 综合管理系统设计与实现

本次期末大作业是本课程的综合实践环节，要求独立完成一个 C# 管理系统。控制台档满分 100，界面档满分 120（100 + 界面 20），两档任选一档。综合运用类与对象、集合、文件操作，培养从需求分析到部署演示的完整开发能力。

作业目标

  • 综合运用本学期所学的 C# 语法、面向对象（类/属性/方法）、集合（List<T>）、文件操作 四大基础
  • 选一档交付：
  • 控制台档 —— 基础线：用 Console 数字菜单操作，满分 100
  • 界面档 —— 进阶线：在逻辑之外加一层 Avalonia 窗体，界面另有 20 分，满分 120

  • 训练独立调试、查资料（含 AI 助教）与表达讲解的能力

题目说明 — 自选主题管理系统

本次大作业不指定单一题目，而是让你从下面的方向中任选一个（或自提一个相近主题），做一个"能增删改查、能保存数据"的管理系统。

形态自己选一档（先按控制台档起步，想加界面随时升上去）：

档位交互方式满分
控制台档Console 数字菜单100
界面档Avalonia 窗体 + 按钮120（100 + 界面 20）

不管选哪一档，这几条底线都必须满足：

  • 管理一类事物的多条记录（如多件药品、多个作品、多个房间…）
  • 对这些记录能 新增、查看、修改、删除（CRUD 四大操作）
  • 数据要保存到文件，关闭程序再打开还在
  • 输入要有校验，填错不能让程序崩

参考案例框架 ① 模型类 — 一条记录长什么样

这三页都用记账本演示（就是示例一的 Record / RecordManager），字段跟上一页那张卡一模一样。先看一条记录怎么表示。
CSHARP
public class Record
{
    public int Id { get; set; }                   // 编号（自动生成）
    public string Date { get; set; } = "";        // 日期
    public string Category { get; set; } = "";    // 类别
    public double Amount { get; set; }            // 金额
    public string Note { get; set; } = "";        // 备注
}
这 5 个属性 = txt 里的一行
1 | 10-01 | 餐饮 | 23.5 | 食堂午饭
5 段对应 5 个属性，顺序不能乱 —— 存盘、读盘都靠这个顺序对上。
换成你的主题：改类名 + 4 个字段
右列 = 换成你自己的主题（括号里是别的题的取法）
Record
→ 你的类名（Book / Medicine / Room）
Id
→ 编号，原样保留
Date
→ 日期 / 时间类字段
Category
→ 分类 / 类型（类别 / 用途 / 房型）
Amount
→ 数值字段（金额 / 数量 / 价格）
Note
→ 备注，多数主题都有
  • { get; set; }：外面能直接读、直接赋值，不用另外写 getter / setter 方法
  • string 给 = ""：没填时也不会是 null，后面拼接不会崩
  • 类名、字段名跟着主题换，结构和顺序别动 —— 动了 Load / Save 就得跟着改
🛠 现在就动手：把 Record 换成你的类名，Date / Category / Amount / Note 换成你主题的字段 —— 这几行写完，第一步就成了。

参考案例框架 ② 管理器 — 一个集合 + 增删改查

还是记账本：多条记录装进一个集合，再给它几个方法。外面的菜单、按钮只调方法，不直接碰 List。
CSHARP
// ② 管理器（1）：一个集合 + 增删改查
public class RecordManager
{
    List<Record> records = new List<Record>();   // 所有记录都在这
    string file = "records.txt";                 // 存在哪个文件

    public void Add(Record r) { records.Add(r); Save(); }
    public void Remove(int id) { records.RemoveAll(r => r.Id == id); Save(); }
    public Record FindById(int id) { return records.Find(r => r.Id == id); }
    public List<Record> All() { return records; }

    public void Update(int id, string newNote)
    {
        Record r = FindById(id);   // 先按编号找到那条
        if (r == null) return;     // 没找到就返回，别让它崩
        r.Note = newNote;          // 改字段
        Save();                    // 改完立刻存
    }
}
  • 四个方法正好是增删改查：Add / Remove / Update / FindById，All() 给菜单列表用
  • 每个方法改完都调 Save() —— 关掉程序数据还在，这就叫持久化
  • r => r.Id == id 是 lambda：在集合里找"编号等于 id"的那条
  • 编号不用用户填，NextId() 自动算 —— 见示例一那页

参考案例框架 ③ 存盘与读盘 — 一行一条

还是记账本：集合只在内存里，一关程序就没了 —— Save() 写进 txt，Load() 时读回来。
CSHARP
public void Save()
{
    List<string> lines = new List<string>();
    foreach (Record r in records)
        lines.Add(r.Id + "|" + r.Date + "|" + r.Category + "|" + r.Amount + "|" + r.Note);
    File.WriteAllLines(file, lines);
}

public void Load()
{
    records.Clear();
    if (!File.Exists(file)) return;   // 第一次运行还没有这个文件
    foreach (string line in File.ReadAllLines(file))
    {
        string[] p = line.Split('|');
        Record r = new Record();
        r.Id = int.Parse(p[0]);
        r.Date = p[1];
        r.Category = p[2];
        r.Amount = double.Parse(p[3]);
        r.Note = p[4];
        records.Add(r);
    }
}
  • Load() 启动调一次、Save() 增删改后调；File.Exists 那行不能省
  • 存 5 段 ↔ 读 Split('|') 5 段，顺序必须一致，改字段要两边一起改

切换到界面档 — 只多一段 XAML

选了界面档，模型层和数据层原样搬过去，只补一个窗口 —— 换的只是外面那层壳，逻辑不动。

多出来的只有 MainWindow 两个文件：.axaml 写界面长什么样，.axaml.cs 写按钮被点时干什么：

XML
<!-- MainWindow.axaml：界面骨架（字段照抄记账本那五个） -->
<StackPanel Margin="20" Spacing="10">
    <TextBox x:Name="dateBox" PlaceholderText="日期 2026-10-01" />
    <TextBox x:Name="categoryBox" PlaceholderText="类别 餐饮 / 交通" />
    <TextBox x:Name="amountBox" PlaceholderText="金额 23.5" />
    <TextBox x:Name="noteBox" PlaceholderText="备注" />
    <Button x:Name="addBtn" Content="新增" Click="AddBtn_Click" />
    <ListBox x:Name="listBox" />
    <TextBlock x:Name="hint" />
</StackPanel>
  • Click="AddBtn_Click" 就是"事件"：按钮被点时，去跑 code-behind 里的 AddBtn_Click 方法
  • 绑定列表：listBox.Items.Add(...)；数据多变就用 ItemsSource = records
  • 提示信息一律用 hint.Text = "..."，Avalonia 没有 MessageBox
  • 注意：Avalonia 12 里 Watermark 改名为 PlaceholderText（老写法还能跑）

示例一 — 新增一条，其余三条照着改

删除、修改、查询在 RecordManager 里几乎是同一段代码 —— 看懂新增这一个，剩下三个换几行就行。

1新建一条
new 一个对象，把读到的值填进字段
2编号自动算
NextId() 现有最大编号 + 1，不让用户填
3加进集合
放进 records 这个 List
4立刻存盘
马上调 Save()，关掉程序数据还在

示例二 — 按钮里其实就三件事

点新增那一刻，代码只做三件事 —— 不管哪个按钮，都是这个顺序：

1读 + 校验
把四个输入框的文本取出来：空没空、数字能不能转 —— 不合格就写提示，直接返回
2调 Manager
一行 manager.Add(...)，存盘、编号都在它里面做完
3刷新 + 提示
列表重新灌一遍数据，底下 hint 写一句"已新增，编号几"

文件这么放 —— 模型层、数据层各一个文件夹，跟界面文件分开：

你的项目名/
├── Models/Record.cs            一条记录长什么样（原样搬过来）
├── Services/RecordManager.cs   管 List + 存盘读盘（原样搬过来）
├── MainWindow.axaml            界面长什么样
├── MainWindow.axaml.cs         按钮被点时干什么
└── records.txt                 数据文件
💡 第 2 步只是调一个方法。Add() 不关心调用它的是菜单还是按钮，它只管把数据存好——这就是"分层"最实际的好处。
  • ⚠️ 删除建议"两次确认"：第一次点只提示，第二次点才真删
  • ⚠️ 列表刷新后会丢选中，所以另存一个 selectedId 记住它

字段还没定？回看可选主题方向那张表里的典型字段举例一列，抄下来改一两个字就能用。

⚠️ 字段一改，Save / Load、菜单项、列表显示（或界面表单）全要跟着改——先把字段写成一张表贴在旁边，再动代码。

改完按顺序自检：① 增删改查各跑一遍 ② 打开 txt 看字段顺序 ③ 每个入口点一遍 ④ 关掉重开看数据还在不在

开发步骤与时间安排

建议按下面的节奏推进（共 2~3 周）；档位不用第 1 天定死，控制台版跑通后再决定要不要加界面也行：

  1. 第1天：定主题 + 列字段 — 确定管理什么、每条记录有哪些字段
  2. 第2~3天：写模型类 + 集合 — 先把 XxxItem 类和 List<XxxItem> 跑通
  3. 第4~6天：做功能 — 先把基础清单做通（增删改查 + 查询）；控制台档配一套菜单，界面档把同样的方法挂到按钮上（直接复用第 2~3 天的 Manager）。有余力再加统计、排序这类亮点
  4. 第7~8天：文件持久化 — 加 Load/Save，确保重启不丢
  5. 第9~10天：校验 + 整理 — 控制台档理顺菜单与提示语，界面档整理布局
  6. 答辩前：写文档 + 演练 — 类图、功能说明、使用说明、截图
💡 卡住先用 AI 助教（课件2 四步法），但最终代码必须自己写、自己讲得清。

温馨提示与常见坑

  • ❌ 套界面前不备份——直接改原项目，界面没做完就交不出能跑的东西。动手前先把控制台版整个文件夹复制一份，界面在副本上做
  • ❌ 只做了增删查，漏了"改"或"查询"——基础清单少一件，功能分直接掉
  • ❌ 菜单只跑一次就退出了——主菜单要用 while (true) 包住，做完一件事回到菜单，只有选 0（退出）才 break
  • ❌ 界面档用 MessageBox.Show——Avalonia 没有，改用 TextBlock
  • ❌ 数据只放内存——没写文件，关掉就没了，持久化分直接丢
  • ✅ 控制台档跑通后想加界面，放手加——Record.cs / RecordManager.cs 不用动，只多一层窗体
  • ✅ 输入一律 TryParse / 判空，避免非法输入直接崩溃
  • ✅ 基础清单做齐之后，有余力就加亮点——统计、排序、导出，功能分里往高给，且花不了多少时间
  • ✅ 每加一个功能就运行试一次，别攒到最后一起调
  • ✅ 答辩重点讲"你的类怎么设计、谁调用谁"，比炫界面 / 炫菜单更得分
