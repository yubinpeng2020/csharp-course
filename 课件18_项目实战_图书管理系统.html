AI 协作开发 — 用 AI 搭脚手架

200 多行代码，一条条敲太慢。把 AI 当搭档，不是替身——它给框架，你填灵魂。

⚠️ 三条铁律——开始前记牢

  1. 只让 AI 写框架：类定义、方法签名、属性声明——这些重复劳动交给它
  2. 业务逻辑必须自己写：判断条件、用户交互、数据校验——你自己想出来才算会
  3. 写完一个方法就关 AI 测一次：不要一口气全问完再写，那样等于照抄

类的设计

🤖 AI 第1步生成完整类 → 🧑 你对照理解每行含义

Book 类 = 一本书的模板——定义了每本书有哪些属性和怎么展示自己。

┌─────────────────────────────────┐
│          Book 对象               │
│  ┌─────────────────────────────┐│
│  │ Title   = "C#入门"          ││
│  │ Author  = "张老师"          ││
│  │ Price   = 45.00             ││
│  │ Stock   = 5                 ││
│  └─────────────────────────────┘│
│  ToString() →                   │
│  "C#入门 | 张老师 | ¥45 | 库存5" │
└─────────────────────────────────┘
CSHARP
class Book
{
    public string Title { get; set; }       // 书名
    public string Author { get; set; }      // 作者
    public double Price { get; set; }       // 价格
    public int Stock { get; set; }          // 库存

    public Book(string title, string author, double price, int stock)
    {
        Title = title; Author = author;
        Price = price; Stock = stock;
    }

    public override string ToString()
    {
        return $"{Title} | {Author} | ¥{Price} | 库存{Stock}";
    }
}
  • 构造方法 Book(...) — 创建对象时一次性填入书名、作者、价格、库存
  • public override string ToString() — ⚠️ 它不是自定义方法，是 override（重写）！
  • C# 里所有类都继承自 object，object 自带 ToString()。不 override 的话，Console.WriteLine(book) 只输出类名 "Book"，没用。
  • override 把它替换成我们自己的格式化输出：「C#入门 | 张老师 | ¥45 | 库存5」
  • 之后所有 Console.WriteLine(book对象) 和 $"{book对象}" 都会自动调用这个版本——写一次，到处用
  • 回忆 课件15：override 就是子类用自己的方法覆盖父类的方法

LoadBooks() — 启动时从文件加载到内存

  📂 books.txt                📋 List<Book> books
  ┌──────────────────┐       ┌──────────────────────┐
  │ C#入门|张老师|45|5│  →   │ Book("C#入门","张老师", │
  │ 算法导论|李教授|89|3│ →   │       45,5)            │
  │ 设计模式|王博士|68|2│ →   │ Book("算法导论","李教授",│
  └──────────────────┘       │       89,3)            │
                             │ Book("设计模式","王博士",│
                             │       68,2)            │
                             └──────────────────────┘
  ① ReadAllLines 读每行      ③ new Book(...) 创建对象
  ② Split('|') 拆成4段       ④ books.Add(book) 加入列表
CSHARP
public static void LoadBooks()
{
    books.Clear();
    if (!File.Exists(FilePath))
    {
        return;
    }
    foreach (string line in File.ReadAllLines(FilePath))
    {
        string[] parts = line.Split('|');
        books.Add(new Book(parts[0], parts[1],
            double.Parse(parts[2]), int.Parse(parts[3])));
    }
}
  • File.Exists — 文件不存在就别读了，程序不会崩
  • ReadAllLines — 把文件所有行读成 string[]
  • Split('|') — 按竖线拆开，每本书存成一行 Title|Author|Price|Stock
  • double.Parse / int.Parse — 文件里读出来都是 string，价格转 double，库存转 int
📁 范例数据文件 books.txt 已准备好（4 列格式 Title|Author|Price|Stock），内容和上面 ASCII 图一样，复制到程序目录就能跑。题2 的 5 列新格式范例见同目录的 books_isbn.txt。

SaveBooks() — 退出时从内存写回文件

  📋 List<Book> books        📂 books.txt
  ┌──────────────────────┐   ┌──────────────────┐
  │ Book("C#入门","张老师",│ → │ C#入门|张老师|45|5│
  │       45,5)           │   │ 算法导论|李教授|89|3│
  │ Book("算法导论","李教授",│ → │ 设计模式|王博士|68|2│
  │       89,3)           │   └──────────────────┘
  │ Book("设计模式","王博士",│ →
  │       68,2)           │   ① foreach 遍历列表
  └──────────────────────┘   ② 拼接成 "Title|Author|Price|Stock"
                             ③ WriteAllLines 一次写完
CSHARP
public static void SaveBooks()
{
    List<string> lines = new List<string>();
    foreach (Book b in books)
    {
        lines.Add($"{b.Title}|{b.Author}|{b.Price}|{b.Stock}");
    }
    File.WriteAllLines(FilePath, lines);
}
  • foreach 遍历列表，每本书拼成一行 Title|Author|Price|Stock
  • WriteAllLines — 把 List<string> 一次性写入文件
  • LoadBooks 用 Split 拆 → SaveBooks 用 $"{}" 拼——对称操作
💡 LoadBooks 和 SaveBooks 是镜像操作：一个读、一个写。数据格式统一用 | 分隔，两边保持一致就行。

Main 只做三件事：启动时加载 → 循环显示菜单 → 退出时保存。所有业务逻辑全在 BookManager，Main 只管分发任务。

CSHARP
class Program
{
    static void Main()
    {
        BookManager.LoadBooks();            // ① 启动时加载数据
        Console.WriteLine("=== 图书管理系统 ===");

        while (true)                        // ② 无限循环，直到用户选退出
        {
            Console.WriteLine("1.添加  2.查看  3.查找  4.借书  5.还书  6.退出");
            Console.Write("选择：");
            string choice = Console.ReadLine();

            switch (choice)                 // ③ 根据输入分发到对应方法
            {
                case "1": BookManager.AddBook(); break;
                case "2": BookManager.ShowBooks(); break;
                case "3": BookManager.SearchBooks(); break;
                case "4": BookManager.BorrowBook(); break;
                case "5": BookManager.ReturnBook(); break;
                case "6": BookManager.SaveBooks(); return;
                default: Console.WriteLine("无效选择"); break;
            }
        }
    }
}

逐行解读：

  • BookManager.LoadBooks() — 启动即加载。程序一打开，把 books.txt 里的数据读到内存。只调一次，放在 while 前面。
  • while (true) — 无限循环。每次操作完回到菜单，直到用户选 6 才退出。
  • switch (choice) — 用户输入 1~6，跳到对应方法。每个 case 一行代码——这就是把业务拆到 BookManager 的好处。
  • case "6" — 先 SaveBooks() 把数据写回文件，再 return 退出程序。保存动作只在退出时执行一次。
💡 记住这个模式：启动时 Load → 循环操作 → 退出时 Save。以后做任何带数据持久化的程序，都是这个结构。

ShowBooks() — 先把查看功能写出来

跑起来就能看到结果，给自己一点正反馈：

  📋 List<Book> books                控制台输出
  ┌──────────────────────┐     ┌─────────────────────────┐
  │ [0] Book("C#入门",…)  │ →   │ [1] C#入门 | 张老师 | ¥45│
  │ [1] Book("算法导论",…) │ →   │ [2] 算法导论 | 李教授 | ¥89│
  │ [2] Book("设计模式",…) │ →   │ [3] 设计模式 | 王博士 | ¥68│

  books.Count = 3               for (int i=0; i<Count; i++)

CSHARP
public static void ShowBooks()
{
    if (books.Count == 0)
    {
        Console.WriteLine("暂无图书");
        return;
    }
    Console.WriteLine($"\n=== 图书列表（共{books.Count}本）===");
    for (int i = 0; i < books.Count; i++)
        Console.WriteLine($"[{i + 1}] {books[i]}");
}
  • 🤨 卫语句（Guard Clause） —— 第 1 行的 if (books.Count == 0) { ... return; } 就是卫语句：
  • 把特殊情况先处理掉、提前 return，后面的主逻辑不用包在 else 里，代码更平、更好读
  • 对比：不用卫语句就得写 if (books.Count == 0) { ... } else { 遍历输出 }，多一层缩进
  • 之后你会经常看到这种写法：if (输入为空) return;、if (未登录) return;……碰到就认得出
  • books[i] 自动调用 ToString()
  • 写完这个就可以 AddBook() 加一本 → ShowBooks() 看一本，边写边测

AddBook() — 先跑通，别怕写错

一开始不用想太多，能把书加进去就行：

┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ 书名：    │ →  │ 作者：   │ →  │ 价格：   │ →  │ 库存：   │
│ "C#入门"  │    │ "张老师" │    │ 45       │    │ 5        │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
                                                    ↓
                                          ┌─────────────────┐
                                          │ books.Add(       │
                                          │   new Book(...)) │
                                          └─────────────────┘
                                                    ↓
                                              ✅ 添加成功
CSHARP
public static void AddBook()
{
    Console.Write("书名：");
    string title = Console.ReadLine();
    Console.Write("作者：");
    string author = Console.ReadLine();
    Console.Write("价格：");
    if (!double.TryParse(Console.ReadLine(), out double price) || price < 0)
    {
        Console.WriteLine("价格不合法");
        return;
    }
    Console.Write("库存：");
    if (!int.TryParse(Console.ReadLine(), out int stock) || stock < 0)
    {
        Console.WriteLine("库存不合法");
        return;
    }

    books.Add(new Book(title, author, price, stock));
    Console.WriteLine("✅ 添加成功");
}
🧐 新东西：TryParse 和 out 参数 —— 之前一直用 int.Parse()，但 Parse 有个致命缺点：用户输入 "abc"，程序直接崩（FormatException）。TryParse 是安全版：不崩，而是返回 true/false 告诉你成没成功。成功的话，结果通过 out 参数带出来：
CSHARP
// Parse：转失败就炸
int x = int.Parse("abc");   // 💥 异常

// TryParse：返回 bool，结果放 out 变量里
if (int.TryParse("abc", out int x))
    Console.WriteLine(x);   // 不执行——TryParse 返回 false
else
    Console.WriteLine("不是数字");  // 走这里
out int price —— "这个方法会帮我把值放到 price 里"，不用先声明变量。
!double.TryParse(...) —— ! 取反，失败就进 if。
|| price < 0 —— 即使转成功了，负数也不合法。
这也是卫语句：输入不合法 → 提示 → return，主逻辑继续往下走。

"帮我给 AddBook 加一个查重功能——如果 books 列表里已经有同名的书，就提示'已存在'并拒绝添加。"

第一次改进：加查重

AI 给你的思路就是：输入书名后，先 foreach 遍历一遍，同名就 return 拦截：

  输入"书名" ──→ ┌──────────────────┐
                │ foreach 遍历 books │
                │ 检查 Title 是否相同  │
                └──────┬───────────┘
                 存在？ │        │ 不存在？
                  ❌    │        │    ✅
            提示"已存在" │        │ 输入作者/价格/库存
              return    │        │     ↓
                        │        │ books.Add(new Book(...))
                        │        │     ↓
                        │        │ ✅ 添加成功
CSHARP
public static void AddBook()
{
    Console.Write("书名：");
    string title = Console.ReadLine();

    // ⬇️ 加的：查重——同名书直接拦掉
    foreach (Book b in books)
    {
        if (b.Title == title)
        {
            Console.WriteLine($"《{title}》已存在，无法重复添加");
            return;
        }
    }

    Console.Write("作者：");
    string author = Console.ReadLine();
    // ... 后面同版本 1
}
🐛 再试一个场景：图书管理员想补货——"C#入门"卖得好，库存从 5 本加到 10 本。结果上面这段代码直接弹「已存在，无法重复添加」……补货也被拦住了。
🤔 这次的问题不一样了：不是"同名→拒绝"，而是"同名→追加库存"。把改好的代码发给 AI，问：
"现在用查重拦住了重复添加，但我还想支持补货：如果书名已存在，询问'追加数量'，加到原来的 Stock 上。"

第二次改进：重名就追加库存

  输入"书名" ──→ ┌──────────────────┐
                │ foreach 遍历 books │
                │ 检查 Title 是否相同  │
                └──────┬───────────┘
                 存在？ │        │ 不存在？
                    ↓   │        │    ↓
          ┌──────────┐  │        │ 输入作者/价格/库存
          │ 输入追加  │  │        │    ↓
          │ 数量: 5   │  │        │ books.Add(new Book(...))
          └────┬─────┘  │        │    ↓
               ↓        │        │ ✅ 添加成功
          b.Stock += 5   │        │
               ↓        │        │
          ✅ 库存已更新   │        │
CSHARP
public static void AddBook()
{
    Console.Write("书名：");
    string title = Console.ReadLine();

    // 查重：找到了就加库存，没找到就新建
    foreach (Book b in books)
    {
        if (b.Title == title)
        {
            Console.Write($"《{title}》已存在（库存{b.Stock}），追加数量：");
            if (int.TryParse(Console.ReadLine(), out int add) && add > 0)
            {
                b.Stock += add;
                Console.WriteLine($"✅ 库存已更新：{b.Stock}");
            }
            return;
        }
    }

    Console.Write("作者：");
    string author = Console.ReadLine();
    Console.Write("价格：");
    if (!double.TryParse(Console.ReadLine(), out double price) || price < 0)
    {
        Console.WriteLine("价格不合法");
        return;
    }
    Console.Write("库存：");
    if (!int.TryParse(Console.ReadLine(), out int stock) || stock < 0)
    {
        Console.WriteLine("库存不合法");
        return;
    }

    books.Add(new Book(title, author, price, stock));
    Console.WriteLine("✅ 添加成功");
}
💡 回头看看我们一起做了什么：一个 AddBook()，从跑通 → 发现重复问题 → 改进 → 发现补货问题 → 再改进，总共磨了三版。每一版都是先发现问题、再分析原因、最后动手改代码。老师只是带着你走，AI 只是你卡住时的帮手——真正想清楚「要加什么功能」的人，是你自己。
  • b.Stock += add 直接修改现存对象的属性——List 存的是引用
  • books[i] 自动调用 ToString()

查找与借还书

先写 SearchBooks() 查找图书——最简单，写完就能搜。再写借书还书——这两个套路一样，写完一个另一个秒懂。

SearchBooks() 查找图书 — 输入关键词，模糊匹配

  输入"关键词" ──→ ┌──────────────────┐
                   │ foreach 遍历 books │
                   │ Title 包含关键词？   │
                   └──────┬───────────┘
                    是？   │        │ 不是？
                     ↓    │        │   ↓
               输出 [i+1]  │        │ 跳过，继续
               books[i]    │        │
CSHARP
public static void SearchBooks()
{
    Console.Write("输入书名关键词：");
    string keyword = Console.ReadLine().ToLower();
    for (int i = 0; i < books.Count; i++)
        if (books[i].Title.ToLower().Contains(keyword))
            Console.WriteLine($"[{i + 1}] {books[i]}");
}
  • ToLower() — 把字母全转小写。用户输入 "c#" 和 "C#" 效果一样，大小写不敏感
  • Contains(keyword) — 判断字符串里有没有这个关键词，"C#入门教程".Contains("入门") → true
  • 这样就实现了模糊查找——不需要记住全名，搜个关键词就能找到
🐛 试一下：搜一个不存在的书名，比如"Python"。屏幕上什么都没显示……用户会以为程序卡死了。
🤔 怎么改进？搜完了如果什么也没输出，就补一句提示。用 bool 标记有没有找到：
CSHARP
public static void SearchBooks()
{
    Console.Write("输入书名关键词：");
    string keyword = Console.ReadLine().ToLower();
    bool found = false;
    for (int i = 0; i < books.Count; i++)
    {
        if (books[i].Title.ToLower().Contains(keyword))
        {
            Console.WriteLine($"[{i + 1}] {books[i]}");
            found = true;
        }
    }
    if (!found)
    {
        Console.WriteLine("未找到匹配的图书");
    }
}
  • bool found = false — 先假设没找到，循环里匹配到了就改成 true
  • if (!found) — 循环跑完了还是 false，说明一本都没匹配到，输出提示

BorrowBook() 借书 — 先跑通，再防崩

借书的逻辑：先列出所有书 → 选编号 → 库存 -1。先写个能跑的：

CSHARP
public static void BorrowBook()
{
    ShowBooks();
    Console.Write("选择要借的图书编号：");
    int index = int.Parse(Console.ReadLine()) - 1;
    if (books[index].Stock == 0)
    {
        Console.WriteLine("❌ 库存不足");
        return;
    }
    books[index].Stock--;
    Console.WriteLine($"✅ 已借出《{books[index].Title}》");
}
  • int.Parse(Console.ReadLine()) - 1 — 用户看到的编号从 1 开始，但 List 索引从 0 开始，所以要减 1
  • if (books[index].Stock == 0) return — 又是卫语句：库存为 0 就拦掉，后面的借书逻辑不用包在 else 里
  • books[index].Stock-- — 库存减 1（-- 是自减运算符，等价于 Stock = Stock - 1）
🐛 试两个边界情况：
- 输入编号 99（根本没有第 99 本书）→ 程序崩溃（ArgumentOutOfRangeException）
- 输入 abc（不是数字）→ 程序崩溃（FormatException）
🤔 这不就是 AddBook 里处理过的老问题吗？加卫语句——输入不合法就 return。编号检查用 index >= 0 && index < books.Count，输入用 TryParse。

第一次改进：加输入保护

CSHARP
public static void BorrowBook()
{
    if (books.Count == 0)
    {
        Console.WriteLine("暂无图书，无法借阅");
        return;
    }
    ShowBooks();
    Console.Write("选择要借的图书编号：");
    if (!int.TryParse(Console.ReadLine(), out int index))
    {
        Console.WriteLine("请输入数字");
        return;
    }
    index = index - 1;
    if (index < 0 || index >= books.Count)
    {
        Console.WriteLine("编号不存在");
        return;
    }
    if (books[index].Stock == 0)
    {
        Console.WriteLine("❌ 库存不足");
        return;
    }
    books[index].Stock--;
    Console.WriteLine($"✅ 已借出《{books[index].Title}》");
}
💡 发现了没？ 这个方法前面一长串全是卫语句：列表为空 → 不是数字 → 编号越界 → 库存不足。所有「不对劲的情况」都在前面拦掉，真正借书的逻辑在最后——干干净净。

ReturnBook() 还书 — 套路和借书一样，但少一个卫语句

注意区分两个概念：books.Count == 0 是「列表里一条记录都没有」，Stock == 0 是「这本书的库存被借光了但记录还在」。借书要拦 Stock == 0——没库存当然不能借。还书不用拦：库存即使是 0，有人来还一本，就变成 1 了。

所以还书的卫语句只保留前三个（列表为空、不是数字、编号越界），去掉库存检查。把借书的代码复制过来，删掉 Stock == 0 那个卫语句，Stock-- 改成 Stock++：

CSHARP
public static void ReturnBook()
{
    if (books.Count == 0)
    {
        Console.WriteLine("暂无图书，无法还书");
        return;
    }
    ShowBooks();
    Console.Write("选择要还的图书编号：");
    if (!int.TryParse(Console.ReadLine(), out int index))
    {
        Console.WriteLine("请输入数字");
        return;
    }
    index = index - 1;
    if (index < 0 || index >= books.Count)
    {
        Console.WriteLine("编号不存在");
        return;
    }
    books[index].Stock++;
    Console.WriteLine($"✅ 已归还《{books[index].Title}》");
}
💡 借书和还书放到一起看——你会发现写代码经常是「抄自己」：差不多的结构，改一两行就行。不是抄别人，是自己积累的套路。

题2（8分）⚠️ 手动验收

给 Book 类加一个「标准书号」字段 BookNo（string 类型）——添加图书时由用户输入，用来唯一标识一本书；它不参与排序、也不参与任何计算，只是个标签。

书号标准规范：必须以 ISBN- 开头，后面是 5 段纯数字、用 - 分隔（去掉 - 共 13 位），例如 ISBN-978-7-02-013948-5。

📁 示例已提供新的数据文件 books_isbn.txt（5 列新格式，首列为书号：BookNo|Title|Author|Price|Stock，里面 3 本书都带了示例书号）。做 题2 时，把 BookManager.FilePath 指向这个文件（或把你的 books.txt 升级成同样的新格式）。
  • 提示：
  • Book 类加 public string BookNo { get; set; }；构造函数和 ToString() 也要带上书号
  • LoadBooks() / SaveBooks() 都必须改：按新格式 BookNo|Title|Author|Price|Stock 读取 / 写出书号列（Split('|') 后书号是第 0 段）
  • AddBook() 用 Console.ReadLine() 读取书号——不要用 int.Parse/long.Parse，书号含字母、连字符或前导零
  • 格式校验：判断是否符合上面的规范（例如用正则 Regex.IsMatch(bookNo, @"^ISBN-(?:\d+-){4}\d$")，需 using System.Text.RegularExpressions;，也可以自己写循环逐个字符判断）；不合规就提示「书号格式错误」并循环重新输入，直到正确
  • 查重：格式合规后，遍历 books 看是否已有相同 BookNo；若重复也提示「书号重复」并重新输入
  • ShowBooks() / ToString() 中把书号展示出来
验收示范：
