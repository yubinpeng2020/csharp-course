继承的"是一种"关系

生活中到处是继承关系。先搞清两个概念：

  • 父类（基类）——被继承的那个，定义共有的东西。比如"动物"：所有动物都有名字、都会叫
  • 子类（派生类）——继承别人的那个，在共有的基础上加自己特有的。比如"狗"：是动物 + 会汪汪叫

来看一张图：

动物（父类）：名字、年龄、叫声
 ├── 狗（子类） — 继承以上全部，再加：汪汪叫
 ├── 猫（子类） — 继承以上全部，再加：喵喵叫
 └── 鸟（子类） — 继承以上全部，再加：会飞

学生（父类）：姓名、年龄、自我介绍
 ├── 大学生（子类）— 继承以上全部，再加：专业
 └── 中学生（子类）— 继承以上全部，再加：年级
  • 子类自动拥有父类的特征（"是什么"），再加自己特有的东西
  • 箭头方向就是"是一种"：狗→动物，大学生→学生
  • 用 C# 的话说：class Dog : Animal —— 冒号后面就是父类

这种关系能解决什么问题？

核心就四个字：代码复用。把共有的东西放在父类，子类只写自己独有的，不用抄一遍。

来看反面教材——不用继承有多痛苦：

CSHARP
class Student
{
    public string Name { get; set; }
    public int Age { get; set; }
    public void Introduce() { ... }
}

// 大学生类——和 Student 几乎一样，只多了专业
class CollegeStudent
{
    public string Name { get; set; }      // ——和 Student 重复！
    public int Age { get; set; }          // ——和 Student 重复！
    public string Major { get; set; }     // 唯一的新东西
    public void Introduce() { ... }       // ——和 Student 重复！
}

既然大学生是一种学生，那直接复用学生的代码不就好了？来看继承的语法：

CSHARP
// 父类（基类）——提供通用代码
class Student
{
    public string Name { get; set; }
    public int Age { get; set; }

    public void Introduce()
    {
        Console.WriteLine($"我叫{Name}，{Age}岁");
    }
}

// 子类（派生类）——继承父类 + 自己的扩展
class CollegeStudent : Student     // : 后面跟父类名
{
    public string Major { get; set; }   // 子类独有字段
}
CSHARP
CollegeStudent cs = new CollegeStudent();
cs.Name = "张三";      // ✅ 继承来的
cs.Age = 20;           // ✅ 继承来的
cs.Major = "计算机";    // ✅ 自己的
cs.Introduce();        // ✅ 继承来的——我叫张三，20岁
  • 子类继承父类的成员，但能访问哪些取决于修饰符（详见下页）

protected — 给子类开的"后门"

CSHARP
class Student
{
    public string Name { get; set; }       // 谁都能访问
    private int score;                      // 只有自己能用
    protected int age;                      // 自己和子类能用
}

class CollegeStudent : Student
{
    public void ShowAge()
    {
        Console.WriteLine(age);   // ✅ protected，子类可以访问
        // Console.WriteLine(score);  // ❌ private，子类也碰不了
    }
}
修饰符子类能访问？说明
public✅ 能外部和子类都能用
private❌ 不能只有父类自己能用，子类也碰不到
protected✅ 能只有自己和子类能用，外部不行

base — 调用父类构造方法

课件12学过 this——它指代"当前这个对象"。在继承体系里，base 指代"父类那一部分"。逻辑很自然：this 是自己，base 是爹。

来看代码——子类的构造方法怎么把 Name、Age 交给父类去初始化：

CSHARP
class Student
{
    public string Name { get; set; }
    public int Age { get; set; }

    public Student(string name, int age)
    {
        Name = name; Age = age;
    }
}

class CollegeStudent : Student
{
    public string Major { get; set; }

    // base(name, age) → 把参数传给父类构造方法
    public CollegeStudent(string name, int age, string major)
        : base(name, age)           // 先调用父类构造
    {
        Major = major;              // 再初始化自己的字段
    }
}
CSHARP
CollegeStudent cs = new CollegeStudent("张三", 20, "计算机");
// 父类的 Name、Age 由 base(name, age) 自动设置

多态 — virtual 与 override

先搞懂概念：多态就是"父类引用指向子类对象，同一个方法调用，结果取决于实际是什么子类"。生活中的多态——遥控器上的"播放"键：按下去，电视播画面、音响播音乐、DVD播光盘。同一个按钮，不同设备，行为不同。

在 C# 里实现多态需要两个关键字：父类用 virtual，子类用 override。

CSHARP
class Student
{
    public string Name { get; set; }

    public virtual void Introduce()        // virtual = "子类可以重写我"
    {
        Console.WriteLine($"我叫{Name}");
    }
}

class CollegeStudent : Student
{
    public string Major { get; set; }

    public override void Introduce()       // override = "我改了父类的版本"
    {
        Console.WriteLine($"我叫{Name}，专业{Major}");
    }
}

现在来看多态的实际效果——声明的是 Student 类型，但执行的是 CollegeStudent 的方法：

CSHARP
Student s1 = new Student { Name = "张三" };
Student s2 = new CollegeStudent { Name = "李四", Major = "计算机" };
//     ↑ 声明为 Student                  ↑ 实际是 CollegeStudent

s1.Introduce();   // 我叫张三        —— 普���学生，走 Student.Introduce()
s2.Introduce();   // 我叫李四，专业计算机 —— 大学生，走 CollegeStudent.Introduce()
//                ↑ 同一个 Introduce() 调用，结果完全不同——这就是多态！

⚠️ 关键规则：

情况结果
父类没 virtual，子类写 override❌ 编译报错
父类有 virtual，子类不写 override正常继承，用父类方法
父类有 virtual，子类写 override✅ 调用子类自己的版本
下页会讲 abstract：abstract 强制子类必须重写，virtual 让子类可选。两者都搭配 override 使用，区别在于父类提不提供默认实现。

抽象类 — 不能 new 的父类

先搞清楚"抽象"二字在编程里是什么意思——它不是你画的抽象画，而是不完整、不具体。

  • 你可以指着笼子里的一只狗说"这是动物"，但不能凭空指着空气说"这是动物"——「动物」本身太模糊，没法具体到一只活物
  • 代码同理：new Animal() 到底叫声是什么？没法回答。所以把它标成 abstract，告诉编译器：别让人 new 我，我只当模板

三个实际作用：

  1. 防止创建无意义的对象：世上没有一只叫"动物"的动物，new Animal() 没意义
  2. 强迫子类统一行为：所有动物都要会叫，但狗叫和猫叫不一样——父类规定"必须会叫"，子类各自实现
  3. 表明设计意图：告诉其他开发者"这个类是模板，别直接用，去继承它"

用 abstract 标记后，这个类只能被继承，不能 new。

CSHARP
abstract class Animal           // abstract = 抽象类，不能 new
{
    public string Name { get; set; }
    public Animal(string name) { Name = name; }

    // 抽象方法：只有声明，没有 { } 实现体，强迫子类必须重写！
    public abstract void Speak();
}

// Animal a = new Animal("?");  // ❌ 抽象类不能 new！
CSHARP
class Dog : Animal
{
    public Dog(string name) : base(name) { }

    // ⚠️ 如果父类是 abstract，子类必须 override 所有抽象方法，否则编译报错
    public override void Speak()
    {
        Console.WriteLine($"{Name}：汪汪！");
    }
}
  • abstract 类 = 模板，不能 new，只能被继承
  • abstract 方法 = 只有声明没有实现，子类必须 override
  • 上面的页面8已讲另一种方案 virtual——父类给默认实现，子类可选要不要改

is 和 as — 类型的判断与转换

学完继承和多态，你已经能写 Animal[] 统一管理猫狗鸟。但有个实际问题——遍历数组时，怎么知道当前这只到底是狗还是猫？"我只想让狗叫，猫跳过"、"我想把狗转回 Dog 类型调用它独有的方法"——这就需要 is 和 as。

is — 判断"它是不是"某个类型

CSHARP
Animal pet = new Dog("旺财");

if (pet is Dog)
    Console.WriteLine("这是一只狗");      // ✅ 输出
if (pet is Cat)
    Console.WriteLine("这不是猫");        // ❌ 不输出
if (pet is Animal)
    Console.WriteLine("肯定是动物");      // ✅ 子类 is 父类 → true
CSHARP
// 实战：遍历动物数组，只让狗叫
Animal[] pets = { new Dog("旺财"), new Cat("咪咪"), new Dog("大黄") };
foreach (Animal a in pets)
{
    if (a is Dog)
        a.Speak();   // 只有狗会叫，猫被跳过
}

as — 安全类型转换（不像强制转换那么容易崩）

CSHARP
Animal pet = new Dog("旺财");

Dog d = pet as Dog;     // ✅ 狗转狗，成功
if (d != null) d.Speak();

Cat c = pet as Cat;     // ❌ 狗不是猫，c = null（不报错！）
if (c == null) Console.WriteLine("这不是猫！");
(Dog)pet 强制转换pet as Dog
转换失败💥 抛异常，不处理程序崩溃返回 null，不崩溃
适用场景100% 确定是同类型不确定，先试试看
💡 一句话：is 问"你是不是"，as 说"试试转成你"。不确定类型时用 as + null 判断比强制转换安全得多。

课堂练习1 — 动物继承

定义 Animal 父类（virtual Speak），派生 Dog 和 Cat 子类各自重写叫声。

代码示例（老师示范讲解）

CSHARP
class Animal
{
    public string Name { get; set; }
    public Animal(string name) { Name = name; }

    // virtual = 允许子类用自己的叫声替换
    public virtual void Speak()
    {
        Console.WriteLine($"{Name} 发出声音");
    }
}

class Dog : Animal
{
    public Dog(string name) : base(name) { }
    public override void Speak() => Console.WriteLine($"{Name}：汪汪！");
}

class Cat : Animal
{
    public Cat(string name) : base(name) { }
    public override void Speak() => Console.WriteLine($"{Name}：喵喵！");
}
CSHARP
Animal[] pets = { new Dog("旺财"), new Cat("咪咪"), new Dog("大黄") };
foreach (Animal a in pets)
    a.Speak();
// 旺财：汪汪！ 咪咪：喵喵！ 大黄：汪汪！
  • 动手：把 Speak() 的 virtual / override 去掉，观察输出有什么变化
  • 进阶：在 foreach 里加 if (a is Dog) 和 if (a is Cat)，分别统计狗和猫的数量
💬 解释说明
  • virtual 是父类的承诺：这个方法的实现子类可以替换
  • override 是子类说：我来提供自己的版本
  • 去掉它们后 foreach 里全输出"发出声音"——失去了多态

本节知识梳理

今天我们一起啃下了这些核心内容：

  • 继承的"是一种"关系：子类"是一种"父类，复用父类成员
  • 这种关系能解决什么问题？：避免重复写公共代码，扩展更方便
  • protected — 给子类开的"后门"：子类能用，类外不能用
  • base — 调用父类构造方法：子类构造用 : base(...) 把参数传给父类
  • 多态 — virtual 与 override：父类用 virtual 留空，子类 override 填自己的实现
  • 抽象类 — 不能 new 的父类：abstract 只当模板，逼子类去实现
  • is 和 as — 类型的判断与转换：is 判类型、as 安全转类型
💡 接下来是「综合练习」——不再是单个知识点的小练习，而是把上面这些串起来解决一个真实小任务。先自己动手写，实在卡住再看答案。

综合练习 — 银行账户体系

综合运用继承：父类定义通用行为，子类扩展独特功能。

期望输入：

  • 张三 创建基础账户，余额1000 → 尝试取1200（应失败）
  • 李四 创建活期账户，余额5000，年利率3% → 计息一次
  • 王五 创建信用卡账户，余额3000，透支额度2000 → 取4000（透支成功）

期望输出：

张三 余额：1000（取1200失败）
李四 余额：5150（年利率3%）
王五 余额：-1000（透支额度2000）
  • 父类 BankAccount：存钱/取钱/Info，virtual 标记可重写的方法
  • 子类 SavingsAccount：新增利息 + 重写 Info（显示利率）
  • 子类 CreditAccount：重写取钱（加上透支额度）+ 重写 Info
  • Balance 用 protected set，子类才能改
  • ___ 是需要你补全的地方

练习

    public void AddInterest()
    { Balance += Balance * ___; }

    public override string Info =>
        $"{Owner} 余额：{Balance}（年利率{___:P0}）";

// ===== 子类2：信用卡账户 =====

{
    public double CreditLimit { get; set; }
    public CreditAccount(string owner, double balance, double limit)
        : ___(owner, balance) { CreditLimit = limit; }

    // 重写取钱：可用透支额度
    public override ___ Withdraw(double amount)
    {
        if (amount > 0 && amount <= Balance + ___)
        { Balance -= amount; return true; }
        return false;

        $"{Owner} 余额：{___}（透支额度{CreditLimit}）";

CSHARP
class BankAccount
{
    public string Owner { get; set; }
    public double Balance { get; protected set; }

    public BankAccount(string owner, double balance)
    { Owner = owner; Balance = balance; }

    // 存钱：金额必须大于0
    public virtual void Deposit(double amount)
    {
        if (amount > 0) Balance += amount;
    }

    // 取钱：不能超过余额，返回是否成功
    public virtual bool Withdraw(double amount)
    {
        if (amount > 0 && amount <= Balance)
        { Balance -= amount; return true; }
        return false;
    }

    // 显示账户信息（子类会重写）
    public virtual string Info => $"{Owner} 余额：{Balance}";
}

class SavingsAccount : BankAccount
{
    public double Rate { get; set; }
    public SavingsAccount(string owner, double balance, double rate)
        : base(owner, balance) { Rate = rate; }

    // 新增：计算利息并存入
    public void AddInterest()
    { Balance += Balance * Rate; }

    // 重写：信息里加上利率
    public override string Info =>
        $"{Owner} 余额：{Balance}（年利率{Rate:P0}）";
}

class CreditAccount : BankAccount
{
    public double CreditLimit { get; set; }
    public CreditAccount(string owner, double balance, double limit)
        : base(owner, balance) { CreditLimit = limit; }

    // 重写取钱：可用透支额度
    public override bool Withdraw(double amount)
    {
        if (amount > 0 && amount <= Balance + CreditLimit)
        { Balance -= amount; return true; }
        return false;
    }

    // 重写：信息里加上透支额度
    public override string Info =>
        $"{Owner} 余额：{Balance}（透支额度{CreditLimit}）";
}
💡 多态进阶：把三种账户放 BankAccount[] 数组里，foreach 统一打 Info。然后加一行——用 is SavingsAccount 判断，只对活期账户调 AddInterest()。

题1（2分）

定义 Shape 抽象类（abstract double GetArea()），派生 Rectangle（宽×高）和 Circle（π×r²）各自实现面积计算。

  • 提示：abstract 方法没有 { } 体，子类必须 override；Math.PI
期望输入：矩形(5, 3) / 圆(r=2)
验收示范：
  • 输出：矩形面积：15
  • 输出：圆面积：12.57

题2（3分）

定义 Employee 父类（Name、virtual CalcSalary() 返回基本工资3000），派生 FullTime（工资不变）和 SalesPerson（重写：3000 + 销售额×10%）。把 3 个不同类型的员工放进 Employee[]，foreach 统一调 CalcSalary() 算总工资。额外要求：在循环里用 is 判断类型，分别统计全职和销售的人数。

  • 提示：if (emp is FullTime) 和 if (emp is SalesPerson)
期望输入：张三(全职) + 李四(销售/50000) + 王五(全职) 放数组统一算
验收示范：
  • 输出：张三工资：3000
  • 输出：李四工资：8000
  • 输出：王五工资：3000
  • 输出：全职2人 销售1人 总工资：14000

题3（4分）

先定义 Account 父类：Username 公开、password 用 protected（子类可见外部不可见）、virtual Login(string pwd) 比对密码返回 bool。再定义 AdminAccount : Account：新增 adminKey，提供自己的 Login(string pwd, string key) —— 在里面先调 base.Login(pwd) 验密码，密码对了再验 adminKey，全是 true 才算管理员登录成功。

  • 提示：protected 字段在子类的 Login 方法里可以直接访问 password；base.Login(pwd) 拿到父类验证结果
期望输入：admin/admin123 + adminKey=secret → 登录成功；admin/wrong + adminKey=secret → 密码错误
验收示范：
  • 输出：admin + 正确密码 → 管理员登录成功
  • 输出：admin + 错误密码 → 密码错误

题4（5分）

用综合练习的银行账户体系：给父类 BankAccount 加 TransferTo(BankAccount other, double amount) —— 从自己账户取钱 Withdraw(amount)，成功则调 other.Deposit(amount) 给对方加钱。然后定义 CreditAccount : BankAccount，重写 TransferTo 支持透支转账。额外要求：转账前用 as 安全地判断对方是否为 CreditAccount，如果是就打印"对方是信用卡账户"。

  • 提示：other as CreditAccount，为 null 就不是信用卡
期望输入：张三(1000) → 转账500给 → 李四(500)
验收示范：
  • 输出：张三 余额：500
  • 输出：李四 余额：1000
